# Modal Transition History Design

## 목적

도구를 열 때 전체 화면 모달이 여러 번 교체되면서 발생하는 깜빡임을 제거하고, `Escape` 키가 현재 화면을 모두 닫는 명령이 아니라 실제 진입 경로의 전 단계로 돌아가는 동작이 되도록 한다.

## 확인된 원인

1. 도구는 `React.lazy`로 불러오며, Tools 런처를 먼저 제거한 뒤 별도의 전체 화면 `tool-loading-overlay`를 표시한다. 모듈 로딩이 끝나면 다시 도구별 전체 화면 오버레이로 교체되어 배경과 blur가 연속해서 다시 그려진다.
2. 공통 모달 패널의 진입 애니메이션이 `opacity: 0`에서 시작한다. 새로운 모달이 마운트될 때마다 패널 전체 밝기가 바뀐다.
3. 모달 표시 여부에 따라 주변 `view-controls`도 opacity 전환을 수행한다. 전체 화면 전환과 동시에 별도의 밝기 변화가 생긴다.
4. 현재 상태에는 도구를 Tools 런처에서 열었는지 대시보드에서 직접 열었는지 기록이 없다. 따라서 `Escape` 키는 `closeSurfaces`를 호출해 모든 화면을 닫거나, 활성 도구만 지운 뒤 런처를 복원하지 못한다.

## 선택한 구조

### 안정적인 전환 셸

- Tools 런처에서 도구를 선택하면 런처를 유지한 채 도구 모듈을 먼저 불러온다.
- 로딩 상태는 현재 런처 패널 안의 진행 표시로 나타낸다. 별도의 전체 화면 로딩 오버레이로 교체하지 않는다.
- 대시보드 도구 버튼에서 직접 열 때에도 모듈을 먼저 불러온 다음 도구 모달을 연다.
- `Suspense` fallback은 예외 상황을 위한 안전장치로 남기지만, 정상적인 사용자 동선에서는 사전 로딩 때문에 표시되지 않는다.
- 빠르게 여러 도구를 선택하더라도 마지막 선택만 열리도록 요청 순번을 검사한다.

### Escape 이력

- Tools 런처에서 도구를 연 경우: `Escape`를 누르면 해당 도구를 닫고 Tools 런처로 돌아간다.
- 대시보드의 도구 버튼에서 직접 연 경우: `Escape`를 누르면 해당 도구만 닫고 대시보드로 돌아간다.
- Tools 런처에서 `Escape`를 누르면 대시보드로 돌아간다.
- 일반 모달에서 `Escape`를 누르면 대시보드로 돌아간다.
- 닫기 버튼과 backdrop 클릭은 기존의 명시적 닫기 동작을 유지한다. 이번 작업에서 전 단계 복귀 의미는 `Escape` 키에 적용한다.

### 모션 정책

- 모달 패널은 opacity와 scale을 바꾸지 않는다.
- 필요한 경우 위치만 짧게 보정하는 절제된 진입 모션을 사용한다.
- 전체 화면 backdrop은 마운트되는 첫 프레임부터 최종 background와 blur를 유지한다.
- 모달 전환 중 주변 컨트롤에는 별도의 opacity 전환을 적용하지 않는다.
- `prefers-reduced-motion: reduce`에서는 위치 모션도 제거한다.

## 상태 모델

도구 상태에 `toolReturnTarget`을 추가한다.

- `launcher`: Tools 런처에서 진입했다.
- `dashboard`: 대시보드에서 직접 진입했다.
- `null`: 활성 도구가 없다.

도구를 열 때 이 값을 함께 기록하고, `Escape` 처리 시 이력에 따라 다음 상태를 결정한다. 도구를 완전히 닫거나 다른 일반 모달을 열 때에는 오래된 이력을 제거한다.

## 적용 범위

- Split 레이아웃과 Classic 레이아웃을 모두 수정한다.
- 데스크톱과 모바일에서 같은 이력 규칙을 적용한다.
- 도구 레지스트리에 사전 로딩 API를 추가한다.
- Tools 런처에 내부 로딩 상태를 추가한다.
- 공통 모달 모션 CSS를 조정한다.
- 단위 테스트와 Playwright 회귀 테스트를 추가한다.

## 완료 조건

- 도구 모듈을 불러오는 동안 Tools 런처가 사라지지 않는다.
- 정상 동선에서 `tool-loading-overlay`가 보이지 않는다.
- 모달 패널의 진입 애니메이션에 opacity 또는 scale 변화가 없다.
- Tools에서 연 도구의 첫 번째 `Escape`는 Tools로, 두 번째 `Escape`는 대시보드로 이동한다.
- 직접 연 도구의 `Escape`는 대시보드로 이동한다.
- Split, Classic, 모바일 동작이 자동 테스트로 고정된다.
- 전체 테스트, lint, production build가 성공하고 운영 환경에 패치 버전이 반영된다.
